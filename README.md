# RAG, Deep Dive — blog source

MkDocs Material site. Source of truth is `docs/*.md` + `mkdocs.yml`.

## Local preview

```bash
python3 -m pip install --user -r requirements.txt
mkdocs serve
```
Open http://127.0.0.1:8000 — hot-reloads on save.

Tutorial pages embed real code live from the [`rag-cookbook`](https://github.com/DhruvMakwana/rag-cookbook) repo at build time (via `pymdownx.snippets`' `url_download`), so building requires network access. If you're on macOS with the python.org installer and see `CERTIFICATE_VERIFY_FAILED`, run:
```bash
python3 -m pip install --user certifi
export SSL_CERT_FILE=$(python3 -c "import certifi; print(certifi.where())")
```
(GitHub Actions' Ubuntu runners already ship a valid CA bundle — this only affects local macOS builds.)

## Adding, editing, deleting content

One Markdown file per page under `docs/`, one line per page in `mkdocs.yml`'s `nav:`. No CMS, no database, no build pipeline beyond MkDocs itself. The revision page (`docs/revision.md`) is generated by `scripts/generate_revision.py` from every page's TL;DR/quiz/flashcard content — re-run it after editing any of those, then rebuild.

## Publishing to GitHub Pages

This folder (`blog/`) is meant to become the **root of its own GitHub repo** — that's what the `.github/workflows/deploy.yml` workflow assumes (GitHub Actions only reads workflows from a repo's root `.github/workflows/`).

1. Push the contents of this `blog/` folder to a new repo, e.g. `github.com/<you>/rag-deep-dive`, as its root.
2. In `mkdocs.yml`, set `site_url`, `repo_url`, `repo_name` to match that repo.
3. In the repo's **Settings → Pages**, set source to the `gh-pages` branch (created automatically by the first Action run).
4. Push to `main` — the site builds and deploys automatically from then on.

If instead you want this to live inside `<you>.github.io` directly (a user/org Pages repo), move `.github/workflows/deploy.yml` to that repo's root `.github/workflows/`, adjust `site_url` to `https://<you>.github.io/`, and point the workflow's `gh-deploy` target per that repo's existing Pages branch setup.

## One-off manual deploy (no GitHub Actions)

```bash
mkdocs gh-deploy
```
